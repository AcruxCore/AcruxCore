# Build a ReAct agent

**What you'll build:** a finance research assistant that looks up stock news and today's date on its own, then answers in plain language — traced end-to-end, but calling OpenAI directly (no gateway).

This tutorial uses the **BYO (bring your own key)** path: model calls go straight to OpenAI with your own key, while AcruxCore still stores the prompt, tool catalog, and traces. Two **client tools** — `finance_research(ticker_symbol)` and `get_todays_date()` — are catalogued in AcruxCore but run by your own code.

:::note[What you'll need]
An [OpenAI](https://platform.openai.com/api-keys) API key (this page calls OpenAI directly, so it needs a real one — no OpenRouter substitute here) and, for the Python tab, `pip install langchain-community yfinance`.
:::

## 1. Create the tools over the API

A tool is a **shell** (name + description) plus an immutable **version** carrying the JSON schema the model reads. Both tools use `"executor": {"type": "client"}` — "my own code runs this," the same contract [Build a tool-calling agent in Python (no SDK)](./build-a-tool-calling-agent-in-python-no-sdk) uses for its `get_weather` tool.

:::tip[Other ways to create tools]
You can also create tools through the [dashboard](../guides/build-and-attach-a-tool) (no code), or declare them in code with [`acrux.tool`](../guides/build-and-attach-a-tool) so the first run auto-registers them in the catalog.
:::

The `@acrux.tool` decorator derives the name, description, and JSON Schema from the function itself. `tools.sync()` reconciles the decorated function with the catalog — creating the tool if it doesn't exist, or committing a new version if the spec changed:

```python
from acruxcore import AcruxCore, acrux

@acrux.tool
async def finance_research(ticker_symbol: str) -> str:
    """Search Yahoo Finance news for a ticker symbol.

    Args:
        ticker_symbol: Stock ticker symbol, e.g. "AAPL".
    """
    # Your implementation here
    ...

@acrux.tool
async def get_todays_date() -> str:
    """Get today's date."""
    return datetime.now().strftime("%Y-%m-%d")

async with AcruxCore() as hub:
    results = await hub.tools.sync([finance_research, get_todays_date])
    for fn, r in zip([finance_research, get_todays_date], results):
        print(f"{fn.__name__}: tool_id={r.tool_id} v{r.version_number}")
```

```text
finance_research: tool_id=c6ffbbff-7e5f-4e6e-acbe-1fd1a027632f v1 committed=True
get_todays_date: tool_id=d0a800d5-a484-4d4f-a9e2-05a715775682 v1 committed=True
```

The docstring becomes the model-facing description, the signature becomes the JSON Schema, and `executor` is automatically set to `"client"`.

## 2. Create the prompt over the API

The prompt's system message is what turns two tools into a ReAct-style agent: it tells the model to reason before acting, names both tools, and says when to reach for each. The version attaches both tools by id, so a single render call returns everything the loop needs.

:::

## 3. Run the agent

There's no SDK call that does this loop for you here — `runToolLoop()` only exists for the gateway and BYO-via-SDK paths. On this page every tab drives the loop by hand:

1. **Render** the prompt (AcruxCore) — one call, gets you messages + tool schemas + the version id.
2. **Complete** — `POST https://api.openai.com/v1/chat/completions`, straight to OpenAI, with your own key. Never through AcruxCore.
3. **Report the `llm` span yourself** — because no gateway saw that call, nothing records it unless you do. `POST /traces` with `kind: "llm"`, the model, `provider: "api.openai.com"` (the host you actually called), and the token usage OpenAI returned.
4. **If the model asked for a tool**, run it locally, report a `kind: "tool"` span onto the *same* trace, feed the result back as a `role: "tool"` message, and go back to step 2.
5. **Once the model stops asking for tools**, print its answer.

This is exactly what the SDK's `chat()` does automatically on the BYO path — pass a
`provider: { apiKey, baseUrl }` option (per-call, or once on the client) instead of routing
through AcruxCore's gateway, and the SDK calls that provider directly, mints a fresh trace
id locally, and reports one `llm` span per round with `costUsd` always empty since the
gateway never saw the call. See [Build a RAG agent without the
gateway](./build-a-rag-agent-without-the-gateway) for a full worked example of that option.
Here you do it explicitly, in two languages, with no SDK at all.

`finance_research`'s implementation differs slightly per language, but both hit **the same real Yahoo Finance endpoint** the source tool calls. The Python tab uses the exact source this tutorial reproduces — [`langchain-samples/assistants-demo`](https://github.com/langchain-samples/assistants-demo)'s `YahooFinanceNewsTool`, via `yfinance`, which manages Yahoo's session/cookie handling internally. Reading `yfinance`'s own source shows exactly what it calls: a plain `GET` to `fc.yahoo.com` for a session cookie, then a `POST` to `finance.yahoo.com`'s internal news-stream API — no crumb token needed for this particular endpoint, just the cookie. The curl tab reproduces that exact two-step call by hand.

## 4. Inspect the trace

Open **Traces** and every run from this page shows up as `react-agent-finance` — one row per script run above, four spans each, and no cost column, because BYO calls never touch the gateway's rate card:

![Traces list showing several react-agent-finance runs, each with 4 spans and a token count but a blank cost column](/img/tutorials/build-a-react-agent/02-traces-list.png)

Open one and the model → tool → tool → model rhythm is exactly what the loop above did: the first `llm` span asked for both tools in the same turn, `finance_research` and `get_todays_date` ran and reported back, then a second `llm` span produced the final answer. This particular trace is from the curl run above, so `finance_research`'s output below is the real Yahoo Finance news text that run got back — expanding the span shows the real argument the model chose and the real result:

![The expanded trace showing an LLM span, a finance_research tool span with input ticker_symbol AAPL and real news headlines as output, a get_todays_date span, and a second LLM span](/img/tutorials/build-a-react-agent/03-trace-detail.png)

Every span here was reported by the script, not by a gateway — that's the whole difference between this page and the rest of the tool-calling tutorials on this site.
